# G1 저장 점수 진단 (2026-10-14)

판정: 업무 후보 간 구분은 소폭 개선에 그쳤고, 정답이 있어도 기권하는 현상이 계속된다. 후보 설명·정답 없는 파생 표본의 의미 적합성은 별도 검토가 필요하다. 추가 학습·모델 호출·설정 변경 없이 저장 자료만 분석했다. final-test를 지표 계산·사례 선정·설정 선택에 사용하지 않았다.

## 범위와 정의

- calibration 457개: 정답 포함 365, 정답 없는 파생 92, 연결 그룹 66. 학습 전후 저장 후보 ID/logit를 동일 example ID로 결합했다.
- selection 374개: 정답 포함 299, 정답 없는 파생 75, 연결 그룹 54. 기존 train_report의 전체 집계만 존재한다. 실행 기록 폴더에서 후보별 score/record 파일을 확인했으나 selection 점수는 없었다. 업무 5개 정확도·정답 순위·정답 유무별 기권 비율은 복원 불가다.
- 업무 선택 정확도: 기권 logit를 제외한 5개 중 최댓값이 정답인 비율. 분모는 정답 포함 사례뿐이다. 기권한 사례도 포함하므로 실제 응답 정확도와 다르다.
- 정답 순위: 업무 5개 중 logit 내림차순 순위. 정답 없는 사례는 순위/업무 선택 정확도에서 제외한다. top-1 및 정답 점수 동률은 없었다.
- 기권: 업무 5개와 예약 기권 후보를 합한 6개 중 기권 logit가 최대인 경우. 임계값·온도 재선택을 하지 않았다. 기존 양수 온도 보정은 이 argmax를 바꾸지 않는다.
- 아래 비율은 발화 기준 기술통계다. 같은 출처의 원본/파생과 그룹 내 발화는 독립 관측으로 가정하지 않으며, 유의성·일반화 성능을 주장하지 않는다.

## calibration 비교

| 항목 | 학습 전 | 학습 후 |
|---|---:|---:|
| 업무 5개 정확도 | 86/365 = 23.56% | 91/365 = 24.93% |
| 정답 순위 1·2·3·4·5 (건) | 86·81·68·67·63 | 91·75·65·68·66 |
| 정답 평균 순위 (낮을수록 좋음) | 2.8356 | 2.8438 |
| 평균 역순위 MRR (높을수록 좋음) | 0.4891 | 0.4942 |
| 정답 포함 사례 기권 | 299/365 = 81.92% | 289/365 = 79.18% |
| 정답 없는 사례 기권 | 80/92 = 86.96% | 78/92 = 84.78% |
| 업무 정답 1위인데 기권 | 64/86 = 74.42% | 65/91 = 71.43% |
| 실제 업무 정답 응답 | 22/365 = 6.03% | 26/365 = 7.12% |

업무 정확도 변화는 +1.37%p(5건)다. 정답 순위 개선 24건, 악화 23건, 동일 318건이며, 평균 순위는 오히려 0.0082 높아졌다. 기권이 업무 정답을 가리는 현상과 업무 후보 간 구분력이 약한 현상 모두 관측된다. 5개 균등 선택의 참고값 20%보다 높지만, 이것만으로 한국어 품질 합격이나 유의한 개선을 주장할 수 없다.

정답 포함/없음 기권 비율 차이는 5.04%p→5.61%p에 그친다. 정답이 없는지를 잘 구분한다고 보기 어렵다. 특히 ‘정답 없음’은 원래 정답 ID가 제거됐다는 생성 규칙이지, 남은 후보가 의미상 모두 부적합하다는 검증 결과가 아니다.

위 값은 upstream train_report의 반올림 집계 그대로다. 기권 포함 정확도를 업무 5개 정확도로 해석하지 않는다. 후보별 기록이 없으므로 calibration의 결과를 selection에 대입하거나 기권 비율을 역산하지 않는다. loss/확률 지표 개선의 원인을 selection 후보 순위 개선으로 확정할 수 없다.

## 연결 검증과 대표 사례

calibration+selection 831개 전부에 대해 원본 ZIP의 행과 발화·과거 맥락을 대조했다. 원본 MAIN에서 만든 도메인/라벨 후보 ID·설명, 정답 포함/제외, 라벨 문자열 유사도로 생성한 방해 후보 집합, 원본/파생 입력 일치, 확정 전체 group/split 상속을 확인했다. 불일치 0, example 중복 0, 두 분할의 그룹 교집합 0. 조사 전후 원본 ZIP·전체 mapping·상속 anchor·두 examples·두 score·학습 보고서의 SHA-256이 모두 그대로였다.

대표 사례는 분류별 저장 순서의 첫 사례이며 final-test에서 고르지 않았다. 원문·전체 맥락·후보 설명·개별 logit는 ignored 로컬 `representatives.private.json`에만 보존했다.

| 사례 요약 | 확인한 연결 | 진단 |
|---|---|---|
| 연락처를 요청하는 부동산 대화 | 원본 정답은 연락처 문의, 동일 후보가 업무 1위 | 학습 전후 모두 기권이 더 높음. 정답 후보를 인식해도 응답하지 않는 사례 |
| 재개발 이후 전망을 묻는 부동산 대화 | 원본 정답은 재건축 아파트 정보, 해당 후보 순위 4→3 | 기권 유지. 발화와 세분화된 원본 라벨의 의미 적합성은 자동 연결 검증만으로 보장되지 않음 |
| 재개발에 오래 걸린다고 말하는 대화 | 원본 정답은 사업 추진 단계, 해당 후보 순위 5→5 | 재건축 시기·계획과 인접한 후보가 있음. 후보 이름만으로 정답을 구분할 충분한 설명인지 검토 필요 |
| 의류 착용 가능 여부를 묻는 파생 사례 | 원래 피팅 문의 ID는 제외, 사용 규칙 등 인접 피팅 후보는 유지 | 정답 없는 사례지만 학습 전후 모두 업무 후보 선택. 의미상 후보 전체 부적합 여부는 별도 검토 필요 |
| 아파트 시세를 묻는 selection 사례 | 원본 시세 문의 정답과 후보 설명 일치 | 연결은 정상. 후보별 점수는 미저장으로 순위 미검증 |
| 시간당 이용 요금을 확인하는 selection 파생 사례 | 원래 이용 가격 문의를 제외했으나 이용 금액 문의 후보가 남음 | 가격/금액 라벨은 이 입력에서 동의 의미일 수 있음. ID 제거만으로 기권 정답을 만드는 규칙의 모호성 확인 |

후보 설명은 자연어 업무 정의가 아니라 ‘도메인 / MAIN 라벨 문자열’이다. 방해 후보 역시 발화 적합성보다 정답 라벨 문자열 유사도로 고른다. 이것이 낮은 정확도의 원인이라는 인과관계는 확정하지 않았지만, 모호한 기권 사례와 인접 라벨의 구분 부족은 실제 표본에서 확인됐다.
