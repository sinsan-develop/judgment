## 1. 판정과 범위

기존 학습 697건을 현재 발화·저장된 과거 맥락 전체·실제 후보집합으로 검토했다. **유일한 정답 216건과 정말 맞는 후보가 없는 64건, 합계 280건을 학습 후보로 선별했다.** 복수 답 264건과 판단 불충분 153건, 합계 417건은 원본과 함께 별도 보존했다. 삭제는 없다.

이는 어울의 수동 의미 검토 v1이며 공식 의도 정의나 도메인 담당자의 확정 정답을 대신하지 않는다. 특히 **280건 중 49건은 기존 정답과 다른 잠정 정답 제안**이다. 원본 gold·후보·맥락·분할은 바꾸지 않았다. 신산님이 이 보고와 잠정 정답 처리 범위를 확인한 뒤에만 비교 학습을 시작한다.

기존 학습·모델 시험·calibration 의미 검토를 반복하지 않았다. 모델 점수나 calibration/selection/test 사례를 선별 판단에 사용하지 않았고, 새 모델 호출·추가 학습·설치·다운로드는 없다.

## 4. 동일 조건 비교 실험안 — 학습 미실행

**권장안은 원본 A와 정리 B의 두 실행을 같은 무학습 모델에서 각각 시작하고, 총 학습 입력 횟수와 정답 포함/없음 비율까지 맞추는 비교다.** 기존 학습 모델에서 이어서 학습하지 않는다. 이미 끝난 과거 run은 참고 기준선이며 비교 실험의 새 A 실행을 대신하지 않는다.

| 조건 | A: 원본 자료 | B: 정리 자료 |
|---|---|---|
| 고유 학습 사례 | 기존 697건·기존 정답 유지 | 선별 280건·확인받은 잠정 정답 사용 |
| 총 입력 노출 | 697회 | **697회**: 업무 정답 558회 + 후보 없음 139회 |
| 입력 구성 | 원본 558/139건 각 1회 | 업무 216건·후보 없음 64건을 유형별 고정 seed 순환, 각 2~3회 |
| optimizer 갱신 | 예상 **88회** | 예상 **88회** |
| 시작 가중치 | 고정 무학습 multilingual 모델 | A와 동일 시작 가중치 |
| 학습 범위 | head-only, encoder 동결 | 동일 |
| loss·후보 처리 | soft-CE, 업무 후보5+기권1, 후보 순서 변경 | 동일 |
| precision·batch | fp32/AMP 끔, micro-batch1, gradient accumulation8 | 동일 |
| 학습률·seed | head 1e-4, encoder 1e-5(동결), seed13 | 동일 |
| 내부 calibration | 0, 재분할 없음 | 동일 |

B의 697회 구성은 선별 자료만 반복 노출하는 고정 학습 목록이다. 제외한 417건이나 검증·시험 자료를 가져와 빈자리를 채우지 않는다. 각 사례의 노출 횟수·순서·원본 그룹을 저장하고, A에도 같은 순서 생성 규칙을 적용한다. 최종 실행 목록은 보고 확인 이후 생성한다. 기존 runner에 이 목록의 원본 ID/그룹과 반복 횟수 검증을 연결하는 최소 준비가 필요하며 아직 구현·실행하지 않았다.

이 비교에서 1 epoch는 **각 697개 입력 목록을 한 번 통과**한다는 의미다. B의 고유 사례 280개를 한 번씩만 학습한다는 뜻은 아니다. 단순하게 두 자료를 각각 자연스러운 1 epoch만 돌리면 A는 88회, B는 35회 갱신하여 학습량이 달라진다. 이를 같은 학습량 비교라고 부르지 않는다. 별도의 자연 1 epoch 비교는 보조안이며 이번 두 실행에 자동 추가하지 않는다.

모델 revision `1720e3e3357cfe1e281542e223f8273b0890ca34`, Laya 소스 `c73908d96ff73c0062c340a11bf7c54ec7d8bc4d`, 기존 고정 의존성과 로컬 실행환경을 유지한다. 실행 시 정확한 제품 코드 SHA·설정·입력 digest·시작 가중치 digest를 두 arm에 기록한다. 엔진 코드는 기존 학습 이후 변경되지 않았다.

### 평가와 해석

- calibration 457건은 온도 보정만, selection 374건은 비교 진단만, test 446건은 고정 비교 평가만 사용한다. optimizer에는 각 arm의 train 목록만 전달한다. selection은 기존 upstream의 epoch 평가 입력이며 역전파·학습 샘플·조기종료·설정 선택에 사용하지 않는다.
- 우선 비교는 후보별 raw 점수와 명시적 기권 argmax로 한다. 두 arm에 온도 탐색 범위 0.25–4.0/41 log-grid 등 동일 계산 절차를 적용하고, G2 운영 임계값은 새로 선택하지 않는다.
- 같은 평가 사례에서 전체 정확도, 업무 후보5 정확도·정답 순위, 정답 포함/없음별 기권, coverage·선택 응답 오류율, NLL/Brier/ECE, 그룹 기반 불확실성과 퇴행을 함께 보고한다. selection 후보별 점수는 앞선 run에서 저장되지 않았으므로 새 비교에서는 두 arm 모두 저장한다.
- 평가 정답·후보·분할은 바꾸지 않는다. calibration에서 이미 의미상 모호한 정답이 확인된 만큼 원래 단일 정답 기준 수치는 참고 비교이며 의미 품질의 확정 증명이 아니다. 기존 검토표를 새 학습 입력이나 정답 변경에 사용하지 않는다.
- 이미 본 test를 새로운 미사용 검증으로 주장하지 않는다. 결과를 보고 추가 튜닝하면 현재 test는 탐색 결과가 되며, 최종 일반화·품질 인수에는 별도로 승인된 미사용 평가가 필요하다.
- B는 반복 노출이 많고 의도·그룹 구성이 줄어든다. 같은 갱신 횟수라도 정리/잠정 라벨 변경/구성 변화 효과가 함께 포함되므로, 각각의 단독 인과효과나 광범위 한국어 성능 향상을 주장하지 않는다.

### 자원·중단·보존

Windows 로컬에서 A/B를 순차 실행하고 동시에 모델을 학습하지 않는다. arm마다 시간30분/RAM24GiB/전체 GPU 점유6GiB, 전체 프로젝트 저장30GiB 상한을 유지한다. 두 arm의 최악 시간 합계는60분이며, 과거 약256초 관측이 같은 소요시간을 보장하지 않는다. 외부 유료 GPU/API와 신규 모델·의존성 다운로드는 계획하지 않는다.

기존 원본·최종 모델·실험 증거는 보존한다. 새 두 arm의 최종 모델·설정·노출 목록·실제 optimizer 횟수·tensor 변화/encoder 불변·reload·평가/자원 증거를 로컬에 남긴다. 모델 파일은 이전 관측에서 약0.60GiB지만 checkpoint 중복·cache까지 포함해 실행 전 실제 디스크를 계산한다. 한도/감시/입력·split 검증 실패 시 중단하며 자동 재시도·CPU 장시간 전환을 하지 않는다. 새 실행의 불필요한 중복 checkpoint만 hash 동일성과 승인된 목록을 확인한 뒤 정리한다. 기존 유일 보존본은 삭제하지 않는다.

## 5. 이번 확인과 다음 경계
