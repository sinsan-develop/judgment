# AI Hub 116 변환·그룹 기준과 G1 데이터 판정

2026-10-14 / 담당 어울 / 사용자 지정 ZIP 읽기 전용 조사. 아래 규칙은 최초 학습 승인안이며, 실제 tokenizer 통과 또는 한국어 성능 합격을 의미하지 않는다.

## 1. 두 스키마의 변환 규칙

| 항목 | 소상공인 9개 XLSX | 공공민원 4개 XLSX |
| --- | --- | --- |
| 현재 발화 | 고객 행의 `SENTENCE` | 민원인 행의 `비식별 데이터` |
| 역할 | `SPEAKER=고객`을 user, 점원을 assistant로 해석 | `화자=민원인`만 학습 현재 발화로 사용 |
| 의도 | 파일 도메인 + 정규화 `MAIN` | 파일 도메인 + `intent`, 차량등록은 `main` |
| 하위 의도 | `SUB`는 추적 정보로 보존, 첫 실행 gold에는 사용하지 않음 | `subintent` 동일 |
| 이전 맥락 | 검증된 순번 블록에서 현재 행 이전의 실제 발화만 사용 | 명시 대화 ID/순서 계약이 없어 빈 맥락 |
| 사용하지 않는 필드 | `MQ/SQ/UA/SA`를 현재 발화 옆에 합쳐 정답 응답을 입력하지 않음. 미래 행 제외 | `question`은 비식별 전 문장일 수 있어 현재 발화 fallback으로 사용하지 않음 |
| 추가 주의 | `QA=A`인 고객 응답도 유지. QA는 화자가 아니라 질문/응답 구분 | 차량등록의 손상된 A열 헤더를 정상 도메인 이름으로 추측 개명하지 않음 |

문자열은 NFKC와 연속 공백 정리로 정규화한다. 자료에 있던 의도 명칭은 제공 taxonomy로 취급하되 발화 문장에서 후보 설명을 만들지 않는다. 후보 설명의 기본은 해당 도메인과 MAIN 명칭이며, 실제 후보 5개 + 명시 기권 1개는 G1 후 별도 token audit를 통과해야 한다. test를 보며 라벨 명칭·설명을 바꾸지 않는다.

동명 의도는 도메인이 다르면 별도 라벨로 센다. 2,677은 이 기준의 라벨 수이지 서로 다른 보편 의미 2,677개를 증명하는 수가 아니다. 의도 뜻의 전문가 확인·의미 중복 병합은 수행하지 않았다.

## 2. 누락·중복·정답 없음 처리

- 점원·상담사 행은 gold 사례에서 제외한다. 검증된 소상공인 블록의 과거 발화로만 참여할 수 있다.
- 현재 비식별 발화가 없으면 제외한다. 공공민원 `question`으로 채우지 않는다.
- MAIN/intent가 없거나 빈 값·`.`·`-`·null 등 placeholder이면 제외한다. 누락 annotation을 기권 정답으로 만들지 않는다.
- 소상공인의 복구 블록은 순번 1에서 시작하고 이후 `SENTENCEID`가 1씩 증가해야 한다. 누락·비숫자·불연속 블록 전체를 격리한다. 순번을 재생성하거나 미래 발화로 맥락을 보충하지 않는다.
- 정규화된 현재 발화+전체 과거 맥락이 동일한데 도메인별 gold가 다르면 모든 해당 사례를 보류한다. 임의 정답을 고르지 않는다.
- 입력+gold 완전 중복은 대표 1개로 줄이되 모든 원본 행·복구 블록의 연결은 보존한다.
- 원본에 ‘후보에 정답이 없음’이라는 gold가 없다. 첫 시험의 정답 없음 사례 400개는 split 확정 후 정상 gold를 후보에서 제외하는 파생 사례로만 계획한다. 이것은 실제 주어진 후보 내 정답 없음이며 의도 라벨 누락과 다르다.
- 개인정보 전체 검사·의미적으로 모호한 모든 문장 판정은 미완료다. 앞선 제한된 정규식 hit 0을 개인정보 안전 합격으로 사용하지 않는다.

## 3. 대화/원본/중복 그룹

`SPEAKERID`는 소상공인 파일마다 2종으로 대화 ID가 아니다. `SENTENCEID`도 여러 번 재시작하는 turn 순번이므로 파일 전체에서 같은 번호를 하나의 대화 ID로 합치지 않는다.

소상공인은 파일 내 순번 1 재시작을 복구 블록 후보로 사용하며 연속성을 확인한 블록만 채택한다. 발견한 후보 블록 5,855개 중 불연속 31개는 격리했다. 이는 **원 제공자가 발급한 검증된 대화 ID가 아니라 실제 행 구조에서 복구한 보수적 블록**이다. 공식 대화 경계의 완전한 증명은 아니다.

공공민원은 파일 전체를 분할 금지 출처 그룹으로 두며 인접 행을 임의 대화로 엮지 않는다. 두 스키마 모두 다음 관계의 전이 연결 성분 전체를 한 split에 배정한다.

1. 동일 복구 블록 또는 공공민원 원본 파일
2. 동일 입력+gold의 모든 출처
3. 정규화 현재 발화의 완전 일치(맥락이 달라도 같은 split)

중복 관계를 직접 쌍만 검사하지 않고 union-find로 전이 폐쇄한다. 의미적 paraphrase 전체의 누출 방지는 아직 입증하지 못했다. 전체 연결 성분 중 최대 그룹은 23,030사례로, ‘네’ 등 반복 발화가 여러 출처를 연결한 결과다. 이 그룹을 쪼개 수량이나 비율을 맞추지 않는다.

## 4. 실제 집계 — token audit 이전

| 단계 | 행/사례 수 |
| --- | ---: |
| 비어 있지 않은 원본 데이터 행 | 95,955 |
| 점원·상담사 등 현재 사용자 발화 아닌 행 제외 | 43,632 |
| 현재 비식별 발화 누락 제외 | 37 |
| gold 의도 누락/placeholder 제외 | 102 |
| 소상공인 순번 불연속 블록의 사용자 행 제외 | 8,761 |
| 동일 입력의 gold 상충 행 보류 | 248 |
| 위 처리 후 유지한 원본 행 | 43,175 |
| 입력+gold 완전 중복의 초과 행 제거 | 260 |
| 최종 고유 입력 사례 | **42,915** |

제외 사유는 역할→발화→gold→순번 블록→QA→상충의 우선순위로 상호 배타 집계했다. 무효 QA(Q/A 외) 제외는 0이다. 각 행을 여러 제외 항목에 중복 계상하지 않았다.

| 범위 | 고유 입력 사례 | 도메인별 의도 | 연결 그룹 |
| --- | ---: | ---: | ---: |
| 소상공인 | 40,427 | 2,562 | 3,042 |
| 공공민원 | 2,488 | 115 | 2 |
| 전체 | **42,915** | **2,677** | **3,042** |

서로 다른 현재 발화 문자열은 **39,366개**, 도메인을 제거한 MAIN 문자열은 **2,537종**이다. 같은 발화에 서로 다른 과거 맥락이 있으므로 입력 사례 수와 다르다. 그룹이 두 스키마를 함께 포함할 수 있어 스키마별 그룹 수를 더하지 않는다.

전체 입력+gold·발화·원본 블록 기준으로 train/calibration/selection/test의 6쌍 교집합은 모두 0이다. 큰 그룹을 먼저 배정해 행 수 70/10/10/10에 맞춘 결과는 다음과 같다.

| split | 연결 그룹 | 입력 사례 |
| --- | ---: | ---: |
| train | 835 | 30,040 |
| calibration | 736 | 4,292 |
| selection | 736 | 4,292 |
| test | 735 | 4,291 |

판정: 정의한 보수적 연결 그룹 단위 4분할은 가능하다. 실제 tokenizer의 head 256/total 1024 예산·후보 48-token 처리 검사는 아직 수행하지 않았으므로 **모델에 실제 전달할 최종 행 수는 미확정**이다. token 초과 행을 조용히 자르거나 통과로 표시하지 않는다.

## 5. 최초 실행 후보 — 실제 학습 미실행

전체 큰 연결 성분과 공공민원 출처 그룹을 첫 2,000행 시험에 억지로 끼워 넣지 않는다. 최대 160사례의 완전한 소상공인 연결 그룹 250개를 seed=13으로 골랐으며, 도메인별 의도 585개를 포함한다. 이는 선정 그룹 전체를 보존한 입력 후보다.

| split | 그룹 | 정답 포함 원본 사례 | 정답 제외 파생 사례(계획) | 합계(계획) |
| --- | ---: | ---: | ---: | ---: |
| train | 138 | 1,120 | 280 | 1,400 |
| calibration | 37 | 160 | 40 | 200 |
| selection | 37 | 160 | 40 | 200 |
| test | 38 | 160 | 40 | 200 |
| 전체 | **250** | **1,600** | **400** | **2,000** |

이 후보의 split 간 입력·현재 발화 교집합도 모두 0이다. 파생 사례는 원본과 같은 그룹/split을 유지하고 후보에서 정상 gold를 제외한다. 아직 후보 목록·파생 JSONL·token cache는 생성하지 않았다. G1 후 실제 token audit 결과와 거절 수를 확인하고 승인 범위 내 최종 수량을 기록한다.

첫 시험은 헤드-only 파이프라인과 실제 갱신 증거를 확인하는 후보이며 전체 한국어 판단 능력의 평가나 공공민원 schema의 학습 검증이 아니다. G2 품질 기준은 미정이다.

## 6. 재현과 보존

`aihub116_review.py`는 ZIP을 메모리에서 읽고 원문 없는 요약과 로컬 전용 출처 그룹 매핑만 만든다. 원본 XLSX를 추출·복사하거나 수정하지 않는다. 이미 제공된 bundled Python/openpyxl을 사용해 실행했고 개발 Python의 의존성 설치는 없었다.

원본 ZIP·`.work` 요약/매핑·실데이터·원문 해시·원문 로그는 Git 제외다. 코드·합성 검증·변환 규칙 문서만 작업 branch에 보존한다. notebook은 조사 코드를 실행하는 재현 진입점이며 원문/원문 예제 출력은 없다.
